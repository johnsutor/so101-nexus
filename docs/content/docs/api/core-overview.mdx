`so101_nexus` provides shared types, configuration classes, scene objects, observation components, asset helpers, and environment registration. Backends live under `so101_nexus.mujoco` and `so101_nexus.warp` and are registered by importing them.

```python
import so101_nexus
```

## Environment registration

Environment IDs are registered with Gymnasium at import time. Importing the top-level `so101_nexus` package alone registers nothing.

```python
import so101_nexus.mujoco  # registers the MuJoCo ids
import so101_nexus.warp    # registers the Warp ids (so101-nexus[warp])
```

| Package | Import | Registers |
|---------|--------|-----------|
| `so101-nexus` | `import so101_nexus.mujoco` | Single-env `MuJoCo*-v1` ids |
| `so101-nexus[warp]` | `import so101_nexus.warp` | Batched GPU-parallel `Warp*-v1` ids |

MuJoCo environments are constructed with `gym.make()`:

```python
import gymnasium as gym
import so101_nexus.mujoco

env = gym.make("MuJoCoPickLift-v1", render_mode="human")
```

Warp environments are natively batched vector environments, so they are constructed with `gym.make_vec()`:

```python
import gymnasium as gym
import so101_nexus.warp

envs = gym.make_vec("WarpTouch-v1", num_envs=4096, device="cuda")
obs, info = envs.reset(seed=0)
```

Warp observations, actions, and rewards are torch tensors on `device`, and autoreset is same-step: the done step already returns the post-reset observation.

Both `gym.make` and `gym.make_vec` accept `config=` and an episode-length keyword:

```python
from so101_nexus import CubeObject, PickConfig

config = PickConfig(objects=[CubeObject(color="blue")])
env = gym.make("MuJoCoPickLift-v1", config=config, max_episode_steps=512)
```

See [Configuration Classes](/docs/api/configs) for the config surface and [Environments](/docs/environments) for the id list, step caps, and observation widths.

### `all_registered_env_ids()`

```python
from so101_nexus.env_ids import all_registered_env_ids

ids = all_registered_env_ids()
```

Returns the SO101-Nexus environment IDs for whichever backends are currently imported: six `MuJoCo*-v1` ids with the MuJoCo backend imported, plus six `Warp*-v1` ids with the Warp backend imported.

| `RobotCameraPreset` | Named preset combining camera mounting parameters |
| `RewardConfig` | Reward component weights with a `compute()` method |
| `EnvironmentConfig` | Base environment parameters (spawn region, observation mode, reset settling, termination) |
| `PickConfig` | Extends `EnvironmentConfig` for pick/lift tasks |
| `PickAndPlaceConfig` | Extends `EnvironmentConfig` for pick-and-place tasks |
| `StackCubeConfig` | Extends `EnvironmentConfig` for stack-cube tasks |

| `LookAtConfig` | Extends `EnvironmentConfig` for look-at tasks |
| `MoveConfig` | Extends `EnvironmentConfig` for directional move tasks |

### Processor APIs

The optional `so101_nexus.processors` subpackage provides LeRobot-style action and observation processor steps and a Gym wrapper that emits LeRobot-shaped observations. It requires the `teleop` extra. See [LeRobot Processors](/docs/api/lerobot-processors) for the full reference and [Installation](/docs/getting-started/installation) for the extras matrix.
