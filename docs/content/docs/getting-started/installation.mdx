## Requirements

- Python >= 3.12. Versions 3.12 and 3.13 are verified in continuous integration.
- Linux or macOS for the MuJoCo backend. Both are exercised in continuous integration.

## Install with pip

```bash
pip install so101-nexus
```

## Install from source

Clone the repository, then sync with [uv](https://docs.astral.sh/uv/):

```bash
git clone https://github.com/johnsutor/so101-nexus.git
cd so101-nexus
uv sync
```

## Verify the install

```python
import gymnasium as gym
import so101_nexus.mujoco  # registers the MuJoCo env ids

env = gym.make("MuJoCoPickLift-v1")
print("Installation OK")
env.close()
```

## Extras

The base install ships the MuJoCo backend and the environment API. Everything else is opt-in.

| Extra | Adds | Install |
| --- | --- | --- |
| `teleop` | Gradio demonstration recorder and leader return IK: `lerobot[dataset,feetech,placo-dep]`, `gradio`, `plotly`, `opencv-python` | `pip install "so101-nexus[teleop]"` |
| `molmoact2` | LeRobot 0.6.1 MolmoAct2 model dependencies; combine with `teleop` for correction collection | `pip install "so101-nexus[teleop,molmoact2]"` |
| `dm05` | Native DM0.5 model and LoRA dependencies; requires LeRobot's source integration | See [Native DM0.5](#native-dm05) |
| `decomp` | Measured convex decomposition of YCB collision meshes (`coacd`, `rtree`, `threadpoolctl`). Without it YCB collision geometry falls back to a single convex hull. The packages ship wheels for the supported platforms | `pip install "so101-nexus[decomp]"` |
| `viz` | Pillow image labels and high-quality resizing in visualization helpers | `pip install "so101-nexus[viz]"` |
| `train` | Torch training dependencies for the PPO and BC examples | `pip install "so101-nexus[train]"` |
| `warp` | GPU-parallel MuJoCo Warp backend. Needs an NVIDIA GPU and CUDA >= 12.8 | `pip install "so101-nexus[warp]"` |
| `rocm` | PyTorch from AMD's ROCm 7.2 wheel index. See below | `uv sync --extra train --extra rocm --no-default-groups` |

Extras combine: `pip install "so101-nexus[teleop,train]"`.

From source, use `uv sync --extra teleop --extra molmoact2` for MolmoAct2 collection.
Other LeRobot policy checkpoints may need their own model dependencies. For example,
`uv run --extra teleop --with "lerobot[smolvla]==0.6.1" so101-nexus teleop ...`
adds SmolVLA dependencies for that invocation. Use the matching LeRobot extra for
other supported policy families. The base install stays independent of LeRobot.


## Native DM0.5

From a source checkout, the `dm05` extra selects a pinned LeRobot source archive automatically:

```bash
uv sync --extra teleop --extra dm05
```

The integration documented in [LeRobot's DM0.5 guide](https://huggingface.co/docs/lerobot/main/en/dm05)
is newer than LeRobot 0.6.1. For pip installations, include the same source archive:

```bash
pip install "so101-nexus[teleop,dm05]" \
    "lerobot[peft-dep] @ https://github.com/huggingface/lerobot/archive/2577da0ef39b47f870592d62d81edc8bce922cc4.tar.gz"
```

The extra retains this project's Transformers version range instead of installing OpenDM's
runtime. The model runs in the teleop process. Weights download through the Hugging Face
cache on first use; ensure your account has access to the model and its license.
See [Teleoperation](/docs/workflow/teleoperation#dm05-so101-pick-cube) for the launch command.

## Native CPU batching

The default installation requires MuJoCo 3.17 or newer, which includes `mujoco.batch.Batch`.
No extra is required. See [Backends](/docs/concepts/backends#native-cpu-batching) for a runnable example and batching limits.

## Try without installing

`uvx` runs the teleop recorder in an ephemeral environment with no permanent install:

```bash
uvx --from "so101-nexus[teleop]" so101-nexus teleop
```

## Training on an AMD GPU (ROCm)

The `rocm` extra installs PyTorch from the [ROCm 7.2 wheel index](https://download.pytorch.org/whl/rocm7.2) instead of the default CUDA build, on Linux x86_64:

```bash
uv sync --extra train --extra rocm --no-default-groups
```

`--no-default-groups` skips the `dev` dependency group. The test suite pins compatible Torch/TorchCodec pairs. Desktop platforms retain Torch `<2.10` and TorchCodec `<0.10`. Linux ARM64 uses Torch 2.11 and TorchCodec 0.11 because those dataset decoder wheels require that pair. LeRobot requires Torch `<2.12`, while the ROCm 7.2 build uses a newer version. `uv` therefore rejects combining `rocm` with `teleop`, `molmoact2`, `dm05`, `dev`, or `test`.

<Callout type="warn">
  `rocm` affects MuJoCo-backend training only, meaning behavior cloning and PPO on CPU-simulated environments. It does not enable the Warp backend: Warp is built on NVIDIA Warp, which has no ROCm/AMD support and always requires a CUDA GPU.
</Callout>

## Warp box collision patch

The optional patch in `patches/mujoco-warp-3.13.0/` replaces box-pair collision detection with the CPU SAT, clipping, and edge algorithm.
It preserves other collision dispatch and uses double-precision intermediates with float32 inputs and outputs.
The normal `warp` extra does not include this patch. The [grasp retention profile](/docs/api/configs#grasp-retention-profile) requires a separate physics configuration.

The patch tests require MuJoCo 3.13, which predates native CPU batching and cannot satisfy this library's current dependency requirement.
From a source checkout, build and test the patch in a separate environment without the library:

```bash
nexus_root="$PWD"
engine_build=$(mktemp -d)
cd "$engine_build"
curl -fL -o mujoco_warp-3.13.0.tar.gz \
  https://files.pythonhosted.org/packages/3f/1a/acc6851ba3b6d2e51d4af0ddb5d1924618c8293512a39abe8521a6f56a5d/mujoco_warp-3.13.0.tar.gz
echo '5d0a25560fed1b6735138159bac6d138cf123d2007e81e1f86304cf15182506c  mujoco_warp-3.13.0.tar.gz' | sha256sum --check
tar -xzf mujoco_warp-3.13.0.tar.gz
cd mujoco_warp-3.13.0
git apply --check "$nexus_root/patches/mujoco-warp-3.13.0/box_box_cpu_sat_port_double.patch"
git apply "$nexus_root/patches/mujoco-warp-3.13.0/box_box_cpu_sat_port_double.patch"
uv build --wheel --out-dir "$engine_build/wheels"
uv venv --python 3.12 "$engine_build/venv"
uv pip install --python "$engine_build/venv/bin/python" \
  pytest \
  "mujoco==3.13.0" "warp-lang==1.15.0" "torch==2.9.1" \
  "$engine_build/wheels/mujoco_warp-3.13.0-py3-none-any.whl"
"$engine_build/venv/bin/python" -m pytest -q \
  "$nexus_root/patches/mujoco-warp-3.13.0/tests/test_patched_box_collision.py"
BOX_TEST_DEVICE=cuda:0 "$engine_build/venv/bin/python" -m pytest -q \
  "$nexus_root/patches/mujoco-warp-3.13.0/tests/test_patched_box_collision.py"
```

The standalone tests compare contact geometry and normal force against CPU MuJoCo for thin fingers, aligned faces, and edge contact.
CUDA tests also exercise captured graphs. The stock dependency fails the thin-finger and edge cases.

This environment validates the standalone patch. It does not support the current SO101-Nexus library.
The patch targets only `mujoco-warp==3.13.0`. Identical collision algorithms do not imply identical trajectories or measured hardware behavior.
